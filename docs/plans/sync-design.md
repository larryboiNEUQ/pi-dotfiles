# 同步设计与选择记录

## Problem

纳管范围、配置所有权和失败规则必须由同一处定义。现有 shell 脚本各自维护范围，无法安全识别冲突或回滚。

## Usage

现有 shell 入口保留。共享命令提供 `audit`、`export`、`apply`、`install` 和 `update`。默认全部纳管内容，`--public` 限定公共范围，`--dry-run` 完全只读。`apply` 不执行插件安装。

## Shape

一份 `packages.json` 作为唯一纳管清单。它声明插件来源、显式 Git 分支、文件资源、JSON 字段、公共或个人分类、外部拥有项、排除项、孤儿文件和持久删除记录。配置内容仍保存在清单指定的仓库文件中。

共享实现采用 Python 标准库。shell 只转换旧入口参数，不各自复制策略。内部单位是 JSON 叶字段、整体数组、整体文本或代码文件，以及按插件身份匹配的来源与过滤配置。缺失、null 和无基线分别表示。

流程先读快照并生成完整计划，再解决冲突和必要确认，然后执行插件与配置操作。JSON 只应用白名单字段，未知内容保留。公共范围在比较之前筛选，个人差异不阻止访客操作。

基线只保存纳管内容的摘要。一个单位只有操作后两侧实际相等时才推进基线。选择保留本机值不能把该值当成共同基线，否则下一次应用会错误覆盖它。权限规则中的顺序具有语义，比较摘要不能排序这些规则。

所有 Git 插件显式声明 `main`。该选择依据本机三个 checkout 的 `main` 和 auto-review 本地 `origin/HEAD=origin/main`，不是联网刷新证据。安装前再核验声明分支存在，不自动切换。

安装每个插件后立即按身份应用其过滤配置。第一个失败停止后续插件。配置事务的快照在插件阶段之后取得，因此回滚不撤销已完成插件注册。回滚检测并发修改，不静默覆盖第三方新写入。

读取边界拒绝重复 JSON 键。写入边界拒绝越界路径、链接和特殊文件。诊断不原样输出子进程 stderr、未知值或秘密。备份在仓库外，权限为 0600。审计与 dry-run 不创建状态或备份。

## Synthesis decision

三个结构不同的候选已完整阅读。A 采用单个深同步实现，B 采用不可变计划与独立事务模块，C 采用资源 reconcile 函数。独立评判模型为 `devin/claude-opus-5.5`，任务 `11c3fef2-28c5-4f2`。

按唯一范围、安全边界、三方比较、插件注册回滚和接口大小评分，A 为 20，B 为 19，C 为 21。选择 A 作为结构基底，理由是保留现有清单、集中策略并减少模块边界。评分是设计判断，不是性能测量。

从 B 采用两侧相等才推进基线和严格输入验证。从 C 采用插件过滤立即生效、插件后配置快照、公共范围预筛选、仓库未知字段拒绝和真实命令 fixture。拒绝新 registry 文件、通用 journal 框架、opaque JSON parser，以及按数组位置写插件过滤。

旧 `--latest`、`--with-settings`、`--sync-locals` 作为新默认行为的兼容提示，不维持两套安装策略。

## Tradeoffs accepted

- 接受最新版不可复现，换取统一来源声明。
- 接受首次差异需要确认，换取不静默覆盖。
- 接受插件升级不可回滚，配置回滚只保证本批配置。
- 接受显式清单新增，换取未知字段不会自动纳管。
- 接受标准库 JSON 在内存中保留未知内容，不增加保留原始字节的复杂 parser。

## Alternatives considered

独立 planner 与 journal 增加共享表示和模块接口，本仓库不需要通用事务框架。新 manifest 文件会迁移已有入口和文档，没有增加同步能力。独立 shell writer 会继续复制规则，因此删除旧实现并迁移调用者。

## Open questions and risks

真实 Pi 插件命令与 Git source 语法需要从安装的 CLI 及源代码确认。本轮不会在真实 Pi 执行这些命令。进程崩溃中断和不合作的外部写入比可捕获失败回滚更难，必须在交接中明确实际验证范围。
