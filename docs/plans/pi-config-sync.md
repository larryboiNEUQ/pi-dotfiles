# Pi 配置同步执行计划

## 授权

依据问卷 Z1=A，只修改仓库与在临时目录验证。真实本机 Pi 保持不变。不提交，不推送。用户随后授权 GitHub tracker 配置与本地票迁移，规格在 https://github.com/larryboiNEUQ/pi-dotfiles/issues/2。

## 完成谓词

命令入口的隔离测试证明规格中的同步、安全、失败和重复执行行为。维护者可重跑同一测试。原有本机配置保持不变。无法验证的行为记为未验证，不算完成。

## 数量与风险

当前范围包括一份纳管清单、三个已有脚本、一个共享同步实现、配置与 agents 快照、术语表、三份 ADR、规格、逐票文件和隔离测试。最高风险是秘密泄漏、非纳管值被覆盖，以及失败推进基线。

## 结构约束

纳管清单集中所有权和字段范围。写入计划显式区分 unchanged、write、restore-default、delete-file 和 uninstall-package。基线仅记录成功的纳管内容，不复制整个配置文件。

## 验证纪律

先运行现有 fixture 测试，保存输出。新增测试从命令入口检查文件内容和退出状态。真实 HOME 不作为写入测试目标。每票只有在验证通过后才标为 VERIFIED。

## 跳过的交付动作

- skip: 提交、推送和 PR。用户明确禁止。
- skip: 真实 Pi 安装或应用。用户明确禁止。
- 已授权并完成 tracker 发布。默认标签、sub-issue 和原生 blocking 关系已通过 GitHub API 核对。
