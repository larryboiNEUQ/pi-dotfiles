# Pi 全局配置同步规格

## Problem Statement

配置所有者在多台机器之间恢复 Pi 插件与个人参数。当前安装和导出范围不同，导出遗漏参数，失败可能继续执行。公开仓库还需要区分个人恢复与访客安装。

本规格依据 `pi-config-sync-v3` 的填写结果。原始答案位于所有者提供的本地 JSON 文件，导出时间为 `2026-10-05T10:06:19.637Z`。JSON 的 draft 状态由 B4 引起。B4 备注明确要求仓库不再同步 MCP 插件，后续本机使用内置 MCP。

## Solution

用一份字段白名单清单驱动审计、导出、应用和安装。默认恢复全部纳管内容，公共模式排除个人参数。所有真实本机安装、应用、删除、提交和推送都不属于本轮执行。

## User Stories

1. 作为配置所有者，我希望以当前本机非密钥配置建立首次仓库基线，避免用旧问卷事实覆盖现状。
2. 作为配置所有者，我希望 npm 跟随最新版，避免多台机器遗留不同固定版本。
3. 作为配置所有者，我希望 Git 跟随声明分支，避免工具在分支消失时静默改选来源。
4. 作为配置所有者，我希望一次恢复全部纳管内容，减少新机器手工设置。
5. 作为访客，我希望选择公共模式，避免导入所有者的个人模型和权限规则。
6. 作为配置所有者，我希望导出默认模型、agents、显示、工作流和权限参数，避免只恢复插件。
7. 作为配置所有者，我希望 LangSmith 参数可恢复且本机密钥保留，避免公开凭证。
8. 作为配置所有者，我希望使用内置 MCP，避免仓库重新安装 adapter 或禁用内置功能。
9. 作为配置所有者，我希望 pi-pstack 文件由其安装器管理，避免两个仓库覆盖同一文件。
10. 作为配置所有者，我希望审计发现新入口和字段但不打印未知值，避免漏管或泄密。
11. 作为配置所有者，我希望待分类项不阻止已纳管内容同步，同时看到覆盖不完整状态。
12. 作为配置所有者，我希望审计和 dry-run 完全只读，方便先检查变更。
13. 作为配置所有者，我希望本机保存同步基线，区分单侧修改和两侧冲突。
14. 作为配置所有者，我希望 JSON 不同字段可合并，数组和文本整体比较。
15. 作为配置所有者，我希望冲突在写入与升级前暂停整批，避免半完成状态。
16. 作为配置所有者，我希望首次应用保留已有差异，只有确认后才覆盖。
17. 作为配置所有者，我希望无交互且需要确认时非零退出，不静默覆盖。
18. 作为配置所有者，我希望配置写入前备份，失败后恢复原状态。
19. 作为配置所有者，我希望插件升级失败立即停止，并知道哪些升级已经完成。
20. 作为配置所有者，我希望只应用参数时不升级任何插件。
21. 作为配置所有者，我希望只有安装和更新升级插件，不在启动、审计或导出时升级。
22. 作为配置所有者，我希望 Git 插件有本地修改时保留修改并停止升级。
23. 作为配置所有者，我希望参数恢复默认、文件删除和插件卸载都有显式记录与确认。
24. 作为配置所有者，我希望删除记录持续保留，晚同步的机器也能收到操作。
25. 作为配置所有者，我希望配置缺失不代表删除，退出纳管不改本机。
26. 作为配置所有者，我希望重复执行不产生新差异，失败项不推进基线。
27. 作为维护者，我希望 quick-install 只 clone 或快进更新，失败立即停止。
28. 作为维护者，我希望工具不自动提交、推送或管理项目配置，保持操作边界。
29. 作为维护者，我希望隔离测试覆盖真实命令入口，方便下一位工程师重跑。

## Implementation Decisions

- 清单是唯一同步范围来源。每项声明来源、类型、公共或个人分类、目标、白名单及整体或字段比较方式。
- 公共参数包括包过滤、plan-mode、footer-no-model、Spark、FFF、Calm 和 goal 的有效字段。默认模型、agents、权限和 LangSmith 参数属于个人范围。
- 新增的速度显示、Cursor 登录、Devin 登录和 LangSmith 追踪插件进入默认清单。登录插件不携带凭证。
- 所有 npm 来源去掉版本号。当前 Git 发布版本固定去掉，不恢复旧问卷中的功能分支。
- MCP adapter 不在清单中。禁用内置 MCP 的扩展条目不从本机导出。保留未知扩展配置，不自动卸载本机 adapter。
- pi-pstack 的三个 agent 与两个配置文件属于外部拥有项。skills 和 Herdr 不纳管。sandbox 配置登记为孤儿文件。
- goal 只导出当前支持的 continuation limits 和 RPC 参数。过期本机字段不删除。
- 快照只含纳管内容。基线位于本机，不入库。快照区分缺失和值为 null。
- JSON 按声明字段或叶字段比较。数组、文本和代码整体比较。相对基线两侧不同改动构成冲突。
- 导出不丢弃仓库单侧改动，应用不丢弃本机单侧改动。冲突必须解决后才执行整批。
- 没有基线时，目标缺失可创建，目标已有且不同必须确认。无交互不支持自动偏好覆盖。
- 写入前计算完整计划。读写边界拒绝越界路径及危险链接。配置事务失败恢复本批写入，插件升级不可回滚。
- 所有执行错误返回非零状态，不继续升级后续插件。基线只记录成功同步内容。
- 显式删除记录区分恢复默认、删除纳管文件、卸载纳管插件。应用前单独列出并确认，记录不会自动清除。
- 全局配置之外的项目配置不管理。Git pull、提交与推送由用户单独操作。

## Testing Decisions

最高测试入口是命令行。测试使用临时 HOME、临时仓库，以及假的 Pi 和 Git 可执行程序。断言文件内容、退出状态和执行记录，不断言内部函数调用方式。

覆盖审计与 dry-run 无写入、公共范围、秘密排除、未知字段保留、外部所有权、首次差异确认、单侧修改、字段合并、数组冲突、整批冲突门禁、无交互失败、配置回滚、插件部分升级、删除确认、持久删除记录、缺失非删除、来源分支失效、Git 本地修改、重复执行和基线更新。新增字段发现必须包含配置内部对象的未知键，不输出其值。

现有脚本的 fixture 测试作为命令入口测试先例。真实 Pi 仅可读取明确批准的非密钥字段。本轮不在真实 HOME 运行应用或安装。

## Out of Scope

- 本轮迁移真实本机 MCP。
- 真实本机安装、应用、升级、卸载和清理过期字段。
- 凭证、设备标识、trust、会话、缓存、日志、备份和安装状态同步。
- skills、Herdr、pi-pstack 文件及项目级配置同步。
- 自动后台更新、自动提交和推送。
